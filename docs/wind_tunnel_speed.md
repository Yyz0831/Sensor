# Wind Tunnel Logger：标定风速模式

工程 `Yyz0831/Sensor`，源码版本 `WT-LAB1-15CM-20261107`，目标板 Nucleo-F411RE。
具体源码快照以 Git 提交号为准；标定参数来源另按下面的采集组名记录。

PlatformIO 环境为 **`wind_tunnel_speed`**。当前参数来自 2026-11-05 **11:25:11** 一组原始 ADC，
适用于该次 **15 × 15 cm 受风板**、同一传感器和安装方式，标定与评分范围为 **2–10 m/s**。
输出是 **m/s**，不是原始 ADC。
现有默认环境仍是 **`wind_tunnel_adc`**，便于继续采集原始数据。
当前风速模式使用 **时间常数 0.2 秒的在线因果 EMA**，再按校零后的 ADC 增量做
**分段线性换算**：12 个拟合节点加固定原点，共 13 个节点。原始 ADC 采集方式不变。
EMA 现在随每个 **5 ms 输出时隙**更新（200 Hz），两次真实 ADC 读取之间使用最新保持值。

同一工程提供三个独立选择的采集/风速环境：

| PlatformIO 环境 | 上传后的功能 | 参数文件 |
| --- | --- | --- |
| `wind_tunnel_adc` | 原始 ADC 采集 | 不做风速换算 |
| `wind_tunnel_speed` | 最新标定参数的风速输出 | `Core/Inc/weight_wind_speed_profile.h` |
| `wind_tunnel_speed_backup` | 旧五组参数的风速输出 | `Core/Inc/weight_wind_speed_profile_backup.h` |

备份环境通过 `WEIGHT_WIND_SPEED_BACKUP_PROFILE` 选择独立参数表，共用当前风速算法：
0.2 秒在线 EMA 每 5 ms 更新，reset 后约 4 秒无风校零，超范围继续输出。
自动标定工具的 `--apply` 只写最新参数表，不覆盖备份表。默认环境仍是 `wind_tunnel_adc`。

## 构建和使用

在 `Sensoring` 目录执行：

```sh
~/.platformio/penv/bin/pio run -e wind_tunnel_speed
# 用户确认本轮原始数据已保存并准备换模式后，再上传：
~/.platformio/penv/bin/pio run -e wind_tunnel_speed --target upload
```

VS Code 可选 **PlatformIO → Project Tasks → wind_tunnel_speed → Upload**。
只点击 Build 不会改变板内固件。本次实现没有自动烧录。

每次安装完成后：

1. 完成原来的机械安装，**关闭风洞风扇**，等板子停止晃动。传感器和受风板留在测量位置。
2. 按 Nucleo 的黑色 **RESET 按钮**，或重新上电。程序会自动开始校零，无须按 B1。
3. 启动时先等待约 0.5 秒让模块稳定，随后 LD2 快闪，自动采集约 4 秒无风读数。
   这段时间保持风扇关闭，不要触碰受风板；从 RESET 到就绪通常约 4.5 秒。
4. LD2 常亮表示零点成功且读数有效。此时才开始 200 Hz 风速输出。
5. 关闭 PlatformIO Monitor，启动课程 Logger 的 `start.command`，选择实际风洞和
   ST-Link 串口，115200 baud 连接。风洞自身的校零与本传感器的校零是两个独立步骤。
6. 开风扇后检查 Logger 中传感器速度是否跟随风洞，再点 **Start Logging**。
   结束后 **Stop & Save**，在文件名注明 `speed`，避免与旧 `adc` 数据混淆。

每次上电或 RESET 都会丢弃旧零点，并自动采集新的无风零点。
也保留蓝色 **B1 用户按钮长按至少 1 秒**的手动重新校零功能；长按只触发一次，
持续按住不会重复校零，松开后再次长按可重新触发。重新校零会立即暂停数值输出。
失败后保持静默，需要关风、检查安装，再按 RESET 或长按 B1 重试，不会自动沿用旧零点。
B1 默认经 SB17 接 PC13，按下为低电平；按键连接依据
[ST MB1136 原理图第 3 页](https://www.st.com.cn/resource/en/schematic_pack/mb1136-default-c04_schematic.pdf)。

### LD2 状态

| LD2 | 状态 | 串口 |
| --- | --- | --- |
| 熄灭 | 上电或 RESET 后短暂等待模块稳定 | 静默 |
| 每 100 ms 翻转，快速闪烁 | 采集 40 次有效零点读数 | 静默 |
| 常亮 | 零点成功，数据有效 | 单列 m/s |
| 每秒连续闪两下 | 校零失败、I²C 失败或数据过期 | 静默 |

校零仍直接采集 **40 次原始 ADC** 求均值，不使用 EMA 输出。
相邻有效读数至少间隔 100 ms，40 次约 4 秒；任何 I²C 失败、
采样中断达到 250 ms，或最大值减最小值超过 **500 counts**，都会拒绝本次零点。
**稳定性检查不能判断风扇是否关闭**：稳定的风也可能通过，所以必须由用户先关风扇。

校零成功后，暂时的通信失败或数据过期会停止输出；恢复有效读数后自动恢复。
超出历史标定范围的有效读数仍继续换算和输出。
若发生安装移动或怀疑零点改变，应关风后按 RESET，或长按 B1 重新校零。

## 转换与适用范围

参数位于 `Core/Inc/weight_wind_speed_profile.h`：

```text
alpha = 1 - exp(-dt_ms / 200)
filtered_adc = previous_filtered_adc + alpha * (raw_adc - previous_filtered_adc)
delta = filtered_adc - 本次无风零点
speed = v_i + (delta - d_i) * (v_(i+1) - v_i) / (d_(i+1) - d_i)
```

`(d_i, v_i)` 和 `(d_(i+1), v_(i+1))` 是包围正 `delta` 的相邻节点。
节点来自这组原始 ADC 的 0.2 秒在线 EMA：每一条串口数据都参与更新，包括重复保持值；
`dt` 使用 CSV 的主机接收时间。这近似板上的 5 ms 输出时钟，不是硬件时间戳的精确回放。
只保留参考风速 2–10 m/s、完成零点窗口后的配对记录，未按预测值或误差删点。
固定拟合 12 个测量区间节点，另加原点，不再搜索节点数。下表仅为阅读舍入，头文件和 CSV 保留完整精度。

| 节点 | ΔADC (counts) | 风速 (m/s) |
| --- | ---: | ---: |
| 0 | 0.000000 | 0.000000000 |
| 1 | 17179.573630 | 2.186571878 |
| 2 | 30853.752817 | 2.335599152 |
| 3 | 48502.950684 | 2.867953023 |
| 4 | 70127.167229 | 3.870285160 |
| 5 | 95726.402453 | 4.419392700 |
| 6 | 125300.656356 | 5.262393273 |
| 7 | 158849.928938 | 6.047866036 |
| 8 | 196374.220198 | 6.533578826 |
| 9 | 237873.530137 | 7.379150655 |
| 10 | 283347.858755 | 7.954337119 |
| 11 | 332797.206052 | 8.597939068 |
| 12 | 386221.572028 | 9.640219146 |

原点到首个拟合节点之间也使用线性插值。**固定原点是约束，不是低风速标定证据**，
这一区间没有本次校准样本。超过末节点时沿最后一段斜率继续外推，
**包括超过 12 m/s 的结果也继续输出，不截断、不因超范围而静默**。

`raw_adc` 的单位是原始 ADC counts；本次无风零点是当次 40 次有效原始读数的均值。
传感器仍在主循环约每 **100 ms** 实际读取一次，读取完成后只更新原始 ADC 缓存。
EMA 在每个 **5 ms 输出时隙**使用最新 ADC 更新，随后查表换算；`dt_ms` 是相邻 EMA
更新时刻的实际毫秒差。正常时 `alpha = 1-exp(-0.005/0.2) ≈ 0.0246901`。
即使 ADC 暂时没有变化，EMA 仍继续向该值靠近；UART 忙时只跳过发送，不跳过滤波。
它只使用当前已获得的读数和上一步状态，不使用未来值、居中窗口或时间前移。
真实读取仍约 10 Hz，**200 Hz 滤波及输出不会增加独立测量的数量**。

校零完成后的第一个输出时隙，用完成校零的当次原始 ADC 初始化滤波历史，
不用零点均值代替该读数，随后开始输出。
RESET、B1 重新校零或读数失败都会清除滤波历史；有效读数间隔达到 **250 ms** 时，
也不沿用旧 EMA 状态。恢复后的有效读数从当次原始 ADC 重新开始，避免混入故障前的平滑值。
节点不随每次校零重新拟合，也不固定使用实验时的绝对 ADC 基线。
当前已取消原始及滤波后 ADC 增量的范围停输检查。超过原先范围不会清除 EMA 历史，
滤波仍按当前读数和已有状态继续更新。所有有限 `delta <= 0` 都输出 `0.000`；
正值使用分段插值或末段外推，不设置固定风速上限。原始值下降后，EMA 输出会逐步跟随。
本次拟合的 EMA 增量范围约为 17,179.574–386,221.572 counts，继续输出不扩大可靠标定范围。

本次只保留风洞参考值 **2 ≤ v ≤ 10 m/s** 的记录拟合和评分。
固件仍可输出低于 2 m/s 或高于 10 m/s 的数值，包括 12 m/s 以上，
这些范围没有本次精度验证。EMA 平滑会带来滞后，没有添加低速死区或时间滞后补偿。
更换受风板、安装角度、传感器、接线或明显改变装配后，需要重新采数据标定；
仅重新校零不能保证原转换曲线仍适用。

## 历史幂律与在线 EMA 回放

这份历史比较按当时的幂律固件 `Read → Format` 路径回放，保留上述旧系数和指数，**没有重新拟合公式**。

| 在线 EMA，τ = 0.2 s，再代入旧幂律 | 0.018752 | 0.136939 |

这是在线算法的离线回放结果，不是上板实测或新的整组留出拟合。

## 串口与故障处理

格式为 **115200、8N1、每行一个非负数、三位小数、LF 换行**，例如：

```text
3.142
3.142
3.142
```

无表头、单位、时间戳、启动文字或调试消息。当前模式不处理串口校准命令。
传感器约每 100 ms 读取一次。主循环读取 I²C，随后短暂屏蔽中断，提交原始值或故障状态；
按键触发重新校零时也在同样的保护下更新共享状态。
SysTick 每 5 ms 执行一次 EMA、查表及格式化，由 UART 中断发送。
正常 5 ms 的 EMA 系数在编译时求出；只有非正常间隔才运行指数函数。
浮点格式化只在这一输出路径调用，不在主循环中同时调用。
因此主循环等待 I²C 时，输出路径仍能继续滤波；发送中的独立缓冲区直到 UART 空闲后才会重用。

**200 Hz 是滤波及输出率，独立测量仍约 10 Hz。**
错过或 UART 忙的时隙会跳过，不突发补发。达到 250 ms 未有有效读数时停止发送，
不发送 `nan`、错误文字或伪造零值；Logger 会显示速率下降或 NO DATA。
过期判断使用真实 ADC 的读取时间；滤波和发送不会刷新该时间。

新速度模式的 `_student.csv/value_raw_mps` 和 `_aligned.csv/student_mps` 才真正是 m/s。
原始 ADC 模式和过去的 ADC CSV 单位不变，两个模式的数据不能混合解释。

## 返回原始 ADC 模式

```sh
~/.platformio/penv/bin/pio run -e wind_tunnel_adc --target upload
```

ADC 模式继续发送原始整数，无须 B1 校零。称重 `weight_i2c`、Mini Scales 和温度环境保留。
